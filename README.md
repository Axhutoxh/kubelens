# 🦀 Freelens Rust (Tauri v2 Desktop)

An ultra-high-performance, bare-metal **Kubernetes IDE & Management Dashboard** built with **Rust (Tauri v2 + Tokio + Axum)** backend and **React 19 + Tailwind CSS v4** frontend.

100% native Rust desktop shell and backend runtime — **Zero Electron or Node.js runtime dependencies**!

---

## 🚀 Performance Highlights

| Metric | Original Freelens (Electron + Node) | **Freelens Rust (Native Tauri v2 + Tokio + Axum)** |
| :--- | :--- | :--- |
| **Desktop Shell** | Heavy Electron Chromium shell | **Native Windows WebView2 via Tauri v2 (Pure Rust)** |
| **Startup Time** | ~3.5 – 4.5 seconds | **< 0.05 seconds (Near-Instant)** |
| **Memory Consumption (RAM)** | ~500 – 700 MB | **~25 – 45 MB** (even with 650+ Pods loaded!) |
| **Desktop Runtime** | Node.js + V8 Engine (~180 MB) | **Single Native Rust Executable (~6 MB, 1.8 MB installer)** |
| **Concurrency Engine** | Single-threaded Node.js event loop | **Multi-threaded Tokio async runtime** |
| **Garbage Collection (GC)** | V8 GC pauses during log streaming | **Zero Garbage Collection pauses (Rust RAII)** |
| **Frontend Bundle** | ~8 MB | **~260 KB initial load (views lazy-loaded)** |

## ⚡ Quick Start

### 1. Run Native Desktop App (Recommended)

```powershell
.\scripts\start.bat
```

The app will:
* Launch instantly as a dedicated native desktop window (1440x900, dark theme).
* Spawn the async Tokio + Axum cluster engine in the background.
* Cleanly exit all background processes and port forwards when closed.

### 2. Frontend Development (HMR & Hot Reload)

```powershell
cd frontend
bun run dev
```
Open **[http://localhost:5173](http://localhost:5173)**.

### 3. Build & Distribute Setup Installer

```powershell
.\scripts\build.bat
```
This produces in `release/`:
* **`kubellens-setup.exe`**: Windows Setup Wizard installer (NSIS) with Start Menu / Desktop shortcuts and an uninstaller.
* **`kubellens.exe`**: Standalone portable executable.

It also refreshes `docs/downloads/kubellens-setup.exe`, the installer served by the website's Windows download button. Commit it with the release.

On **macOS / Linux**, build locally with:
```bash
cd frontend && bun install && cd ..
bun x @tauri-apps/cli@2 build          # Linux needs libwebkit2gtk-4.1-dev first
```

### Releasing for Windows, macOS and Linux

Push a version tag and the [release workflow](.github/workflows/release.yml) builds every platform and publishes a GitHub Release:
```bash
git tag v1.2.0 && git push origin v1.2.0
```
| Platform | Release asset |
| :--- | :--- |
| Windows | `kubellens-setup.exe`, `kubellens.exe` (portable) |
| macOS (Apple Silicon + Intel) | `kubellens-macos-universal.dmg` |
| Linux | `kubellens-linux-amd64.AppImage`, `kubellens-linux-amd64.deb`, `kubellens-linux-x86_64.rpm` |

The website links to `releases/latest/download/<asset>`, so new releases show up there automatically.

### 4. Project Website (GitHub Pages)

The showcase site lives in [`docs/`](docs/index.html) and is plain HTML — open it in a browser to preview.
It deploys via [`.github/workflows/pages.yml`](.github/workflows/pages.yml) on every push to `main` that touches `docs/`.
One-time setup: **Repo → Settings → Pages → Source: GitHub Actions**.

## ✨ Features Implemented in the Suite

### New in 1.1
* **Pod Shell**: Full interactive terminal in any running container (`kubectl exec -it` over a native PTY + xterm.js). Supports vim/top/tab completion, container switching and reconnect.
* **Live Metrics**: CPU / memory columns on Pods and utilisation bars on Nodes (requires metrics-server; degrades gracefully without it).
* **Rollout History & Rollback**: Per-deployment revision list (images, change cause, age) with one-click rollback.
* **Multi-select Pods**: Checkbox selection with Shift-click ranges; bulk delete, copy names, and **combined logs** from many pods (or every pod of a deployment) in one colour-coded stream.
* **Command Palette (Ctrl+K)**: Fuzzy-search pods, deployments, services, views, namespaces and contexts.
* **Column Chooser**: Show or hide table columns on Pods and Deployments (defaults: Name, Image Tag, Status, Ready, CPU, Memory, Actions); remembered per table. Deployments gain Status and per-deployment CPU / memory totals.
* **Helm Releases**: List releases in any status; view user/all values, manifest, notes and history; roll back or uninstall (uses the local `helm` CLI).
* **Custom Resources**: Browse every installed CRD, grouped by API group, using each CRD's own printer columns.
* **Node Maintenance**: Cordon, uncordon and drain (with optional force) from the Nodes view.

### Core
* **Multi-Cluster Context Discovery**: Auto-detects all contexts from `~/.kube/config` with live switching.
* **Workloads & Pods Management**: Real-time phase tracking, restart counters, IP addresses, node assignment.
* **Deployments**: Desired/ready replicas, container image tags, replica scaling modal, rolling restarts.
* **StatefulSets**: Pod replica status, headless service bindings, scaling modal, rollout restarts, YAML editor.
* **DaemonSets**: Desired, scheduled, ready, up-to-date counts, node selector display, rollout restarts.
* **Batch Jobs & CronJobs**:
  * **Jobs**: Completions, active status, duration tracking, conditions, and rerun triggers.
  * **CronJobs**: Schedule expressions, active/suspend status toggling, manual "Trigger Job Now".
* **Storage Management (3-in-1)**:
  * **PersistentVolumeClaims (PVCs)**: Bound status, requested/actual capacity, volume mode, access modes.
  * **PersistentVolumes (PVs)**: Capacity, reclaim policy, claim bindings, storage class.
  * **StorageClasses**: Provisioners, reclaim policy, volume binding mode, volume expansion, default class badges.
* **Cluster Nodes**: Capacity vs allocatable CPU/Memory, ready conditions, taints, node info.
* **Namespaces Management**: Active/terminating status, filter by namespace, create namespace modal.
* **ConfigMaps & Secrets**: Full inspection modals with inline editing, data saving, Base64 decoding/encoding.
* **Services & Ingresses**: Cluster IPs, port mappings, external IPs, ingress routing rules, TLS hosts.
* **Live SSE Log Streaming**: Async Server-Sent Events stream for container logs directly through Tokio process pipes.
* **Manifest Inspector & Live Apply**: Interactive Monaco-style YAML editor with live cluster apply.
* **Port-Forwarding**: Background session manager with instant start/stop and auto-assigned local ports.
